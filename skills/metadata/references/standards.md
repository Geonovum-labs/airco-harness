# Recognizing metadata standards and profiles

Start with stable identifiers, namespace IRIs, declared profiles, graph types, and publisher documentation. Detect the serialization separately: Turtle, JSON-LD, RDF/XML, an HTML or PDF catalog, or a JSON API response may express the same role. A namespace prefix is arbitrary; use the full IRI. For JSON-LD inspect `@context` and `@type`; for non-RDF input, cite the field path and the profile or docs that explain it. Never upgrade a resemblance into formal conformance.

| Source | Recognition signals | Read as / watch out for |
| --- | --- | --- |
| [DCAT 3](https://www.w3.org/TR/vocab-dcat-3/), [DCAT-AP](https://interoperable-europe.ec.europa.eu/collection/semic-support-centre/solution/dcat-application-profile-data-portals-europe), [DCAT-AP-NL 3.0](https://docs.geostandaarden.nl/dcat/def-st-dcat-ap-nl30-20250526/) | `http://www.w3.org/ns/dcat#`; `dcat:Catalog`, `dcat:CatalogRecord`, `dcat:Dataset`, `dcat:Distribution`, `dcat:DataService`; a declared profile or documented profile use | Catalog entry vs described item; dataset vs available representation; service vs endpoint URL vs endpoint description. A DCAT term alone gives no specific `-AP` profile or version. |
| [CSSV (Core Standards and Specifications Vocabulary)](https://interoperable-europe.ec.europa.eu/collection/common-assessment-method-standards-and-specifications-camss/solution/core-standards-and-specifications-vocabulary-cssv) | `http://data.europa.eu/2sa/cssv#`; `cssv:Specification`, `cssv:Standard`, or a declared CSSV profile | Read the entry as metadata **about a specification**. The [CSSV 2.0 ontology](https://isa-camss.github.io/CSSV/) subclasses `cssv:Specification` under `dcat:Dataset`, so a dataset-shaped entry can describe a specification rather than the domain data. Inspect the published specification artifact and version separately. |
| [MIM 1.2](https://docs.geostandaarden.nl/mim/def-st-mim-20240613/) | Declared MIM version, model metadata, MIM metamodel types or documented model stereotypes and a publisher artifact | Read domain meaning or data structures at levels 2–3. A generic model, UML diagram, schema, or HTML catalog is not proof of MIM. Prefer the actual cited version of the model and standard. |
| [NL-SBB 1.0](https://docs.geostandaarden.nl/nl-sbb/def-st-nl-sbb-20241010/) / [SKOS](https://www.w3.org/TR/skos-reference/) | `http://www.w3.org/2004/02/skos/core#`; `skos:ConceptScheme`, `skos:Concept`, definition, label, and relation terms; declared NL-SBB profile or documented use | Vocabulary evidence (level 1). Read scheme, language and source separately. Broader/narrower and mapping relations are not UML inheritance or field bindings. SKOS does not establish NL-SBB conformance. |
| [DQV](https://www.w3.org/TR/vocab-dqv/) | `http://www.w3.org/ns/dqv#`; `dqv:QualityMeasurement`, `dqv:isMeasurementOf`, `dqv:computedOn`, `dqv:value`, quality annotations or certificates | Identify subject, metric, value, units, method and date where supplied. `dqv:computedOn` identifies the measured resource; `qb:dataSet` can instead group observations. A measurement for one distribution is not an overall rating or evidence of present-day quality. |
| [PROV-O](https://www.w3.org/TR/prov-o/) | `http://www.w3.org/ns/prov#`; `prov:Entity`, `prov:Activity`, `prov:Agent`, `prov:wasDerivedFrom`, `prov:wasGeneratedBy`, qualified relations | Identify source, transformation and responsibility only as far as the published chain goes. Derivation is not equivalence, endorsement or a complete workflow; record provenance is not automatically data provenance. |

## Practical crosswalk

| Role | Example of what to follow | Do not assume |
| --- | --- | --- |
| Entry describes item | `foaf:primaryTopic` from a DCAT catalog record; a documented catalog response's item identifier | The record's publication or update timestamp is the dataset's. |
| Dataset has representation | `dcat:distribution`; [Schema.org `distribution`](https://schema.org/distribution) pointing to a `DataDownload`; or a publisher-documented representation listing | A `DataDownload` covers downloadable forms, not every DCAT distribution (which may be accessed through a service). |
| Access and service | `dcat:accessURL` for access; `dcat:downloadURL` for direct download; `dcat:accessService` from distribution to service; `dcat:servesDataset` from service to dataset; `dcat:endpointURL` and `dcat:endpointDescription` from service | An access URL is a direct file URL; an endpoint URL is itself a contract; serving a dataset proves field bindings or conformance. |
| Declared specification | `dct:conformsTo` to a standard or specification identified by the source, potentially described in a CSSV registry | The claim was validated, the target is always a domain model, or a claim scoped to a dataset applies to every service. |
| Other references | `dct:references`, `dct:relation`, a model-registry entry, `dcat:landingPage`, or publisher link | Discoverability implies a normative or bidirectional relationship. |
| Element-to-element binding | A publisher mapping with source and target versions, paths/IDs, transformations and applicable operation or representation | Similar names, datatypes or a common theme establish a mapping. `dcat:theme` only supplies classification, not a field definition. |
| Quality or provenance | DQV/PROV assertions, a dated quality report or documented lineage note | Free text is a DQV measurement, generic attribution is PROV, or a claim transfers to related resources. |

For unfamiliar standards or publisher-specific fields, record the observable role and original expression, read the local profile or specification if it is relevant, and mark unidentified terms or unclear mappings as such.
